## What this repo is, and why it exists

A standalone, public, pip-installable Python package: a
`scikit-learn`-compatible transformer that turns financial time series into
**path signature** features. See `ROADMAP.md` for the concrete build plan.

This is meant to become the **flagship CV project** — the one with the most
detail, the one Filip can talk through for 20 minutes in an interview — not
another closed-loop backtest. Two prior projects already cover derivatives
pricing and systematic backtesting (see "Relationship to `quant` repo"
below); they are finished and are *not* being folded into this one. This
project's job is to demonstrate something different: real open-source
research software, built on the specific pure-math strength (rings/algebras)
rather than generic quant-finance plumbing.

### Why signatures, specifically

The signature of a path lives in the tensor algebra
$T((V)) = \bigoplus_n V^{\otimes n}$ — a noncommutative associative ring
under the tensor product. The log-signature lives in the free Lie algebra
generated by $V$. Signatures satisfy Chen's identity (concatenation ↔ tensor
product) and the shuffle-product identity (a Hopf algebra structure — a
commutative ring dual to the tensor algebra). This is a direct application
of free-algebra/ring-theory machinery, not decoration — those identities are
also how correctness gets verified in tests (numerically check the shuffle
relations hold).

### Why this is meant to be actually useful, not just impressive

The math is already solved (Lyons' group, 15+ years of rough-path-theory
literature) and fast low-level compute libraries already exist
(`iisignature`, `RoughPy`, `signax`, `esig`) — bare tensor-algebra
primitives with no finance framing. **Important honesty constraint:**
`sktime` already ships a `SignatureTransformer` (Generalised Signature
Method, Morrill et al. 2020), so "nobody packaged signatures" is false and
must never be claimed. The real gap, which the README must state precisely:
sktime targets panel classification (pre-segmented series → one vector);
quant pipelines need *causal rolling-window features on a continuous
stream* with strict no-lookahead alignment, finance-specific preprocessing
defaults (lead-lag → quadratic variation), and sliding-window updates that
cost O(1) per tick in the steady state via Chen's identity + the group
inverse — which no high-level library exposes. Differentiator: "the missing
middle layer between signature engines and quant practice," with the
streaming engine as the genuine mathematical contribution (see `ROADMAP.md`).

## Research standards (carried over from `quant`)

- Strict temporal discipline: train/validation/test splits, no lookahead
- Transaction costs included in any backtest that trades
- Regime-based decomposition when comparing performance across time
  (2000-07, 2008-09, 2010-19, 2020-22, 2023-25 — same windows as
  `multi-asset-trend`, for comparability)
- Honest conclusions — if signature features don't beat the baseline on some
  slice of the data, say so in the README, not just the good results
- Exposure-adjusted metrics when comparing strategies with different average
  exposure
